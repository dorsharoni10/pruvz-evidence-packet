# Captured example

Unlike the authored examples in [`examples/valid/`](../valid/), the packet here was **composed from real product output**: the two API responses of one action from a live run of the Pruvz product demonstration, captured on 2026-08-01 and composed with the bundled `npm run compose` — the conformance proof described in [`docs/CONFORMANCE.md`](../../docs/CONFORMANCE.md).

- `verified-refund.captured.packet.json` — a refund action that ran end to end: the agent's claim, the relayed execution receipt, two independent read-backs (CRM and billing), and the Worker's `VERIFIED` ruling.

Provenance notes:

- The demo runs against deterministic controlled source systems (identified in the packet's `source` fields as `billing-sandbox` and `crm-sandbox`); every payment, ticket and refund in this packet was generated by that controlled environment for this run. There is no customer data, and nothing to redact — which is the point of capturing from the demo environment.
- The data is verbatim product output. Nothing was edited after composition; the automated tests validate this file with the same two-layer validation as every other example.
- A detail worth noticing, because it is real: `executionStartedAtUtc` is `null` even though the action is `COMPLETED` — the completion transition is legal straight from `RECEIVED` when the agent reports completion without ever reporting an execution start. The published examples and the validator's consistency rules account for this.
